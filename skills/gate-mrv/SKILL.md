# GATE-MRV 三层校验流程（移植自 One 系统 Moat 门禁）

> 来源：One 系统 `CLAUDE.md` GATE-8 铁律 + `tests/moat/gate_memory.sh`
> 核心理念：**站在巨人肩膀上，但巨人也会说错话——用当下证据校对旧经验。**

任何需要修改代码/配置/文件或做重要决策的任务，**动手之前必须走完三层校验**：

```
M (Memory)   查内部记忆与踩坑经验   → 昨天
R (Research) 按触发条件查外部世界   → 当下
V (Verify)   交叉验证 + 质疑旧经验  → 以当下可验证的事实为准
```

## 一、GATE-0 分类声明（动手前必做）

任何工具调用前，先输出分类声明（写在回复开头，不可省略）：

```
[GATE-0 分类声明]
类型: 执行 / 调试 / 决策 / 优化 / 问答
意图: 用户的深层需求一句话
信号: 我识别到的所有关键信息（含错误/异常/上下文）
假设: 我准备确认的关键假设（没有的话写"无"）
方案: 一句话方案概述
```

违规范例：用户说"启动 X" → 直接查进程 → **违规**（未分类、未识别信号）。
合规范例：用户贴错误日志 → 先输出分类声明 → 识别为"调试"类型 → 确认后再动手。

## 二、M — 查记忆（必做）

动手前先检索内部经验，禁止重复造轮子：

- 搜索已有记忆、踩坑经验、方案文档
- 检索不到时，**明确说"未找到相关记忆，按全新方案处理"**，不能默认自己没查过
- 这是"站在巨人肩膀上"的第一步：先看别人/自己踩过的坑

## 三、R — 查外部（按触发条件，命中必须查）

以下场景**必须**补充外部检索（web 搜索 / GitHub / 官方文档 / 最新新闻），否则视为未完成校验：

| 触发条件 | 例子 |
|---|---|
| 版本升级 / 依赖兼容性 | 依赖包升级后行为变化 |
| 第三方库 / API / 开源项目 | GitHub 仓库状态、issues、npm 包 |
| 实时信息 | 新闻 / 政策 / 价格 / 服务状态 |
| 内部记忆无覆盖的新领域 | — |
| 内部记忆时间戳过旧（>30 天） | 旧经验先质疑再采信 |

纯逻辑 / 架构 / 内部代码问题 → **不需要**查外部，避免拖慢节奏。

## 四、V — 交叉验证（必做）

把记忆与外部证据对比：

1. **交叉比对**：记忆说 A、外部证据说 B → 冲突时**以当下可验证的事实为准**，不盲目信记忆
2. **追溯时效**：记忆沉淀 >30 天就要怀疑是否还成立（事物不是一成不变的）
3. **反向纠错**：被推翻的记忆要标记失效/改写，**不能只进不出**

> 反模式：把「查过记忆」当「遵守了门禁」，查完无脑照做 = 把过去的错误复制到未来。

## 五、完整闭环

```
动手前 = GATE-0 分类声明
       → M 查记忆
       → R 查外部（触发条件命中才查）
       → V 交叉验证
       → 改代码 / 执行
       → 验证结果
```

## 六、一句话版本

> **站在巨人肩膀上，但巨人也会说错话——要用当下的证据给他"校对"，校对完还要把他记错的改过来。**
