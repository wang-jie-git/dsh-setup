# 工作台维护协议 Workbench Maintenance Protocol

## 项目结构（2026-08-21 重组）

```
📁 dsh 项目/                          ← DSH 工作区（所有操作数据）
├── README.md                         ← 总索引（所有目录入口，自动维护）
├── 📁 1.技术文档/                    ← 技术文档（架构决策、问题修复记录）
├── 📁 2.学习笔记/                    ← 学习笔记（教程、研究报告）
├── 📁 3.dsh插件自研发/               ← 自研插件开发记录
├── 📁 4.自建技能/                    ← 自建 SKILL 文档
├── 📁 5.已装外部技能插件/            ← 外部技能/插件清单
└── 📁 6.自媒体工作台插件/            ← 自媒体工作台数据
    ├── README.md                     ← 仪表盘（作品列表、工具状态、更新日志）
    ├── 📁 作品/                      ← 所有下载/产出的视频、图片、文案
    └── 📁 ... (工作台数据)

📁 1.自媒体工作台/                    ← 工作台面板插件开发项目（独立发布）
├── README.md                         ← 项目总索引
├── 📁 1.架构设计/                    ← 架构设计文档
├── 📁 2.开发记录/                    ← 开发过程记录（P0, P1, ...）
├── 📁 3.发布配置/                    ← 打包签名、发布相关
├── Fork 仓库: Wjzhong123/self-media-workbench
├── 上游: KivenBig/obsidian-act-console
└── 格式规范: kepano/obsidian-skills
```

## 核心原则

1. **每次操作后自动更新**——DSH 每完成一项任务，必须更新工作台对应笔记
2. **更新有标准格式**——使用下面定义的模板，保持一致性
3. **不删旧记录**——只追加，不覆盖（历史可追溯）
4. **总索引 README.md 始终反映最新状态**——各目录的 README 是入口
5. **日期标记**——所有更新标注日期（YYYY-MM-DD 格式）

## 更新规则（按操作类型）

### 1. 下载视频/素材
**更新位置**：`6.自媒体工作台插件/README.md` 的「作品列表」章节
**格式**：
```markdown
### YYYY-MM-DD
- `作品/<文件名>.mp4` — [标题]（平台，大小，时长）
```
**同时**：验证文件确实在 `作品/` 目录下

### 2. 安装/更新插件或 skill
**更新位置**：`6.自媒体工作台插件/README.md` 的「插件清单」表格
**格式**：在表格中新增/更新行
**同时**：如果插件是自研的，在 `3.dsh插件自研发/` 创建或更新笔记

### 3. 工作台面板插件开发操作
**更新位置**：`1.自媒体工作台/2.开发记录/` → 创建开发记录
**同时**：更新 `1.自媒体工作台/README.md` 总索引的开发路线状态
**注意**：这是独立项目，代码在 `~/Desktop/self-media-workbench`，Fork 自 KivenBig/obsidian-act-console

### 4. 写技术文档/修复记录
**更新位置**：`1.技术文档/` 对应笔记
**同时**：更新 `README.md` 总索引，在「文档清单」新增链接

### 5. 创建自建 skill
**更新位置**：`4.自建技能/` 创建新笔记
**同时**：更新 `README.md` 总索引

### 6. 视频内容理解/分析
**更新位置**：`6.自媒体工作台插件/README.md` 的「内容理解记录」章节
**格式**：
```markdown
### YYYY-MM-DD — [视频标题]
- 核心内容：...
- 关键帧：...
- 标签：...
```

### 7. 日常操作日志
**更新位置**：`6.自媒体工作台插件/README.md` 的「操作日志」章节
**格式**：
```markdown
| 日期 | 操作 | 详情 | 产出位置 |
|------|------|------|---------|
| YYYY-MM-DD | 下载视频 | [标题] | `作品/xxx.mp4` |
```

## 更新工具

使用 MCP filesystem 工具写文件到 Obsidian vault：
```
mcp__filesystem__write_file
  path: "/Users/mac/Documents/ObsidianVault/2.项目/dsh 项目/<目标路径>"
  content: "<markdown 内容>"
```

或：
```
mcp__filesystem__write_file
  path: "/Users/mac/Documents/ObsidianVault/2.项目/1.自媒体工作台/<目标路径>"
  content: "<markdown 内容>"
```

## 查询当前状态

当用户问"工作台现在什么状态""看看进度"时：
1. 读取 `dsh 项目/README.md` 总索引 — 了解各目录概况
2. 读取 `6.自媒体工作台插件/README.md` — 了解最新操作和作品列表
3. 读取 `1.自媒体工作台/README.md` — 了解面板插件开发进度
4. 读取 `作品/` 目录 — 了解所有已下载素材
5. 汇总汇报给用户

## 日启动/日结束协议

### 日启动（用户开始工作时）
1. 读取工作台状态（两个 README）
2. 汇报当前进度：作品数、待办事项、最新操作、插件开发状态
3. 询问用户今天想做什么

### 日结束（用户说"今天就这样"）
1. 汇总今天所有操作
2. 更新操作日志章节
3. 更新总索引 README.md（两个项目都更新）
4. 简要汇报今日成果

## 反面清单
- ❌ 不要覆盖已有内容（只追加，不覆盖）
- ❌ 不要修改 `作品/` 目录下的文件（作品是只读产出）
- ❌ 不要删除旧记录（历史可追溯是工作台的核心价值）
- ❌ 不要在没有实际操作时无意义更新（空更新浪费空间）
- ❌ 不要混淆 `dsh 项目/`（操作数据）和 `1.自媒体工作台/`（插件开发项目）
