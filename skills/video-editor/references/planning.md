# 视频策划流程（规划先行，批准后执行）

**核心原则：先理解素材 → 策划主题 → 出剪辑方案 → 用户批准 → 才执行剪辑。**

不要拿到素材就直接剪。剪辑决策必须建立在"理解全部内容"之上，且最终方案由用户拍板。这借鉴了 director-mode-video-editor 的透明编辑理念：每个决策要看得见、可修改、可追溯。

## 阶段总览

```
P0 素材全量理解（probe + analyze 每个素材）
   ↓
P1 内容盘点与主题策划（提炼主题/钩子/叙事线）
   ↓
P2 制定详细剪辑方案（镜头表 JSON + 章节 + 配音/字幕/BGM 计划）
   ↓
P3 呈现方案给用户（请求修改、批准）
   ↓
P4 批准后执行（按镜头表剪辑，出片质检，交付）
```

**P0-P3 不产生任何成片**，只产出文字方案；用户批准（或修改后再批）才进入 P4。

---

## P0 素材全量理解

对**每一个**素材文件执行：

1. `video_probe <file>` — 元数据：时长/分辨率/帧率/编码/音轨/字幕流
2. `video_analyze <file>` — 内容：场景变化、ASR 转写、屏幕文字、高光时刻
3. `video_ask <file> "这个片段讲了什么/关键信息是什么"` — 定点补充

产出：`scripts/media-manifest.md`（素材清单表）

| 文件 | 时长 | 分辨率 | 内容摘要 | 关键镜头(时间点) | 可用性 |
|---|---|---|---|---|---|
| clip1.mov | 45s | 1080x1920 | 产品开箱 | 0:05 开箱, 0:20 特写 | ★★★ |
| clip2.mov | 30s | 1920x1080 | 使用演示 | 0:10 操作过程 | ★★ |

**判定**：
- 素材是否覆盖主题所需内容
- 哪些镜头值得进成片（标时间点）
- 是否需要补拍/换素材（缺口要明确告诉用户）

---

## P1 内容盘点与主题策划

基于 P0 的全量理解：

1. **一句话主题**：这条视频讲什么？（用户没有给主题时，从素材内容提炼 2-3 个候选）
2. **目标观众**：给谁看，希望他们看完做什么
3. **平台适配**：抖音/视频号/B站/小红书？决定 9:16 或 16:9、时长、节奏
4. **叙事线**：按短视频结构模板组织（见 project-layout.md）
   - 钩子（0-5s）→ 背景（5-20s）→ 核心信息（20-45s）→ 过程体验（45-90s）→ 结论（90-120s）→ 结尾引导
5. **内容取舍**：哪些素材用、哪些砍、哪些放 B-roll

产出：`scripts/brief.md`（策划简报，简短）

---

## P2 制定详细剪辑方案

把策划转成**机器可执行 + 人可审查**的方案：

1. **镜头表**：`scripts/shot-plan.json`（格式见 project-layout.md）
   - 每个片段：素材文件、入点/出点、时长、字幕文案
   - 卡片/信息卡内容
2. **章节结构**：markdown 里列出每章 → 用哪些镜头 → 想传达什么
3. **配音/字幕计划**：
   - 是否需要配音（edge-tts 音色候选 2-3 个）、旁白文案
   - 字幕风格（底部白字黑底 / 居中标题）
4. **BGM/音效计划**：曲风、音量比例、淡入淡出点
5. **画面处理计划**：需要调色/滤镜/抠像/马赛克的具体镜头
6. **成片参数**：分辨率、帧率、编码、目标平台预设（qc-checklist.md）

产出：`scripts/edit-plan.md`（剪辑方案，含镜头表引用）

---

## P3 呈现方案，请求批准

向用户呈现 **edit-plan.md 的核心内容**（不要贴全文，给可读摘要）：

```
📋 剪辑方案 v1
━━━━━━━━━━━━━━━━━━━━━━
🎯 主题：{一句话主题}
👥 目标观众：{...}
📱 平台：{...}（9:16 / 16:9，目标时长 {X}s）

📖 章节结构：
1. 钩子 0-5s     → clip1 0:00-0:05 ｜ 字幕“...”
2. 背景 5-20s    → clip2 0:10-0:25 ｜ ...
3. ...

🎙 配音：{音色候选1 / 候选2}，旁白文案见下方
🎵 BGM：{曲风}，音量 ~25%，结尾淡出
🎨 画面处理：{调色意图 / 需要马赛克的镜头}

⚠️ 需要确认：
1. 主题方向 OK 吗？
2. 配音用哪个音色？（可先试听）
3. 有镜头要换/删吗？
```

**请求用户"同意 / 修改"**：
- 用户说"同意/批准" → 进入 P4
- 用户提出修改 → 更新方案 → 再次呈现（最多 2 轮内收敛，若反复大改说明 P1 没问清，先回 P0/P1）

**未经批准不得进入 P4。** 这是硬性门禁。用户不在场时只做 P0-P2 的只读分析，不做任何成片操作。

---

## P4 批准后执行

按批准后的 shot-plan.json 执行：

1. 建目录骨架（project-layout.md）
2. 按任务类型选配方（ffmpeg-recipes / kdenlive-recipes / capcut-recipes / tts-subtitles）
3. 生成片段 → 拼接 → 配音字幕 → 调色 → 导出
4. 过 QC（qc-checklist.md）
5. 交付：产物路径 + 参数 + 质检结果
6. 写记忆：成品路径、方案、踩坑（tags 含"视频剪辑"）

---

## 例外情况

- **用户直接给了明确剪辑指令**（如"把 0:10-0:20 剪出来配乐"）：这是明确的单一指令，可跳过 P1-P2 直接从 P0 探测后执行，但仍需先探明素材再动手
- **用户明确说"不用给我看方案，直接剪"**：尊重指令，但执行后交付时说明方案假设
- **涉及付费/云端资源（如 cutcli 云端渲染、视频生成）**：必须事先征求批准

## 策划质量检查

- [ ] 每个素材都 probe + analyze 过了（没有盲剪）
- [ ] 主题一句话能说清
- [ ] 镜头表每个片段有依据（来自素材内容，不是空想）
- [ ] 配音/字幕/BGM/画面处理计划齐全
- [ ] 方案已呈现给用户并获得批准
